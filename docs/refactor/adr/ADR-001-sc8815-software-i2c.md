# ADR-001：SC8815 固定使用 PA6/PA7 软件 I2C

- 状态：Accepted
- 日期：2026-08-22
- 依据：`docs/rules/hardware_rules.md`

## 背景

当前控制板的 SC8815 通信网络虽然历史命名为 I2C3，但实板确认该硬件 I2C 接线不可直接使用。当前有效连接为：

- `PA7 = SCL`；
- `PA6 = SDA`；
- `PA5 = SC8815_INT`；
- `PB1 = #CE`；
- `PB0 = PSTOP`。

SC8815 7-bit 地址固定为 `0x74`。PA6/PA7 具有外部 2 kΩ 上拉。

## 决策

当前硬件版本的 BMS V2 固件固定使用 PA6/PA7 GPIO open-drain 软件 I2C 驱动 SC8815。

不把“迁移到硬件 I2C”作为本硬件版本的软件优化项。只有原理图、PCB 和 `.ioc` 共同变更并完成新硬件验证后，才允许建立新的 ADR 修改该决策。

## 实现约束

1. 线序由产品配置编译期固定为 `PA7=SCL`、`PA6=SDA`。
2. 运行期 ACK 失败不得自动交换 SDA/SCL。
3. 软件 I2C 由 `ScServiceTask` 单一拥有；ISR 只通知事件。
4. 每个事务具有绝对超时和明确错误码。
5. 支持显式总线恢复：检查 SDA、最多 9 个 SCL 恢复脉冲、STOP、再次检查空闲状态。
6. 不在完整事务期间长时间全局关中断；仅对不可分割 GPIO 边沿或共享状态使用短临界区。
7. 必须测量：总线频率、最大事务时间、最大关中断时间、SCL/SDA 上升时间和 NACK/卡线恢复行为。
8. `PSTOP` 紧急停充不依赖软件 I2C。

## 后果

优点：

- 与当前实板事实一致；
- 不需要修改 CubeMX/HAL 生成配置；
- 可以针对 SC8815 时序建立独立、可注入故障的 driver。

代价：

- CPU 占用和时序抖动高于硬件 I2C；
- 需要严格限制临界区并进行 WCET 测量；
- 必须自行实现超时、总线恢复和边沿时序验证。

## 验证

- Host fake-bus 单元测试；
- PA6/PA7 逻辑分析仪时序；
- SDA 拉低、NACK、异常中断故障注入；
- 充电运行期间任务 deadline 和 IRQ-off 测量；
- 所有失败路径确认 `PSTOP=1`。
