# BMS CAN FD 遥测协议 V1.1

## 1. 适用范围

本协议用于 24 V/6S BMS 的整车只读遥测，并保留旧板测查询兼容接口，提供：

- 上位机按命令查询；
- BMS 每 1 s 主动上报状态；
- 低电量、严重低电量、恢复和故障边沿立即补发 TPDO1。

V1.1 不定义充放电 MOS、预放电、故障清除或参数写入命令。CAN 报文不能绕过 BQ76952 的硬件保护和本机电源状态机。

## 2. 链路约定

| 项目 | 约定 |
| --- | --- |
| CAN 标识符 | 11 位标准帧 |
| 帧格式 | ISO CAN FD，BRS 开启 |
| 仲裁段/数据段速率 | 500 kbit/s / 4 Mbit/s（整车静态通信已验证） |
| 仲裁段/数据段采样点 | 75% / 75% |
| 仲裁段/数据段 SJW | 250 ns / 250 ns；各控制器按自身 CAN 时钟换算 TQ |
| 字节序 | 多字节字段均为 little-endian |
| 有符号数 | 二进制补码 |
| 应用层校验 | 无；使用 CAN FD 硬件 CRC |
| 协议版本 | `0x01` |

当前工程开启 BRS 和自动重传。驱动返回成功只代表报文已进入发送 FIFO，不代表对端已经收到；关键状态变化会立即补发 TPDO1，最终状态仍以周期 TPDO1 收敛。软件检测到 bus-off 或待发帧持续阻塞时会取消 TX 请求并重启控制器，HAL 进入 ERROR 时还会执行 DeInit/Init。总线上必须存在正确供电、两端终端匹配且能够 ACK 的另一节点。

## 3. 报文 ID

| 标准 ID | 方向 | 名称 | 触发方式 |
| ---: | --- | --- | --- |
| `0x183` | BMS → 上位机 | TPDO1 状态摘要 | 启动后立即一帧，此后每 1 s；关键状态变化立即补发 |
| `0x600` | 上位机 → BMS | 旧板测查询请求 | 仅独立板测兼容，整车网络禁用 |
| `0x580` | BMS → 上位机 | 旧板测查询应答 | 仅收到旧板测查询时发送，整车网络禁用 |

扩展帧、远程帧、经典 CAN 帧和未开启 BRS 的业务帧不属于整车协议。当前硬件接收过滤器只把旧板测 ID `0x600` 送入应用层；其他节点报文仍由控制器在物理层正确接收并 ACK，但不会进入 BMS 应用层。

## 4. 公共字段

查询请求长度固定为 3 字节。

| Byte | 查询请求 `0x600` |
| ---: | --- |
| 0 | 协议版本 `0x01` |
| 1 | 查询命令 |
| 2 | 上位机事务序号 |

查询应答公共头如下：

| Byte | 查询应答 `0x580` |
| ---: | --- |
| 0 | 协议版本 `0x01` |
| 1 | 回显查询命令 |
| 2 | 回显事务序号 |
| 3 | 执行结果 |
| 4... | 命令数据 |

执行结果：

| 值 | 含义 |
| ---: | --- |
| `0x00` | 成功 |
| `0x01` | 不支持的协议版本 |
| `0x02` | 不支持的命令 |
| `0x03` | 当前数据无效；应答体仍用于诊断 |
| `0x04` | 请求长度或格式错误 |

版本错误、未知命令和格式错误统一返回 8 字节，Byte 4～7 固定为 `0`；`DATA_INVALID` 仍返回对应命令的完整应答体，便于诊断当前采样值。

## 5. 查询命令

### 5.1 `0x01` 状态摘要

旧板测查询应答长度为 32 字节，Byte 0～3 保留旧查询公共头；整车 TPDO1 不使用该私有公共头。

| Byte | 类型/单位 | 内容 |
| ---: | --- | --- |
| 0 | `u8` | 协议版本 |
| 1 | `u8` | `0x01` |
| 2 | `u8` | 查询事务序号或主动上报序号 |
| 3 | `u8` | 查询结果；周期帧固定 `0` |
| 4～5 | `u16` | 状态标志 |
| 6 | `u8` | 电源状态机状态 |
| 7 | `u8` | BQ76952 FET Status |
| 8 | `u8 / %` | SOC；无效时 `0xFF` |
| 9 | `u8 / %` | SOC 可信度 |
| 10 | `u8 / %` | 容量 SOH；未完成学习时 `0xFF` |
| 11 | `u8 / %` | SOH 可信度 |
| 12～15 | `u32 / mV` | 总压；当前实现为 BQ Stack Voltage 镜像 |
| 16～19 | `i32 / mA` | 电流；正数充电，负数放电 |
| 20～21 | `u16 / mV` | 最低单体电压 |
| 22～23 | `u16 / mV` | 最高单体电压 |
| 24～25 | `u16 / mV` | 单体压差 |
| 26～27 | `i16 / 0.1 °C` | 电芯温度 |
| 28～29 | `u16` | 逻辑电芯均衡位掩码 |
| 30 | `u8 / %` | 健康趋势评分，与容量 SOH 分开 |
| 31 | `u8` | 保留，固定 `0` |

状态标志：

| Bit | 名称 | 为 1 时的含义 |
| ---: | --- | --- |
| 0 | `BQ_ONLINE` | BQ 通信正常且六节电芯采样有效 |
| 1 | `FAULT_ACTIVE` | APP 故障摘要有效 |
| 2 | `DISCHARGE_ALLOWED` | 电源状态机允许放电 |
| 3 | `SOC_VALID` | SOC 字段有效 |
| 4 | `SOH_VALID` | 容量 SOH 已至少完成一次有效学习 |
| 5 | `SOH_LEARNING` | 正在进行满电到空电的容量学习 |
| 6 | `LOW_SOC` | 低电量状态已锁存 |
| 7 | `CRITICAL_SOC` | 严重低电量状态已锁存 |
| 8 | `CAN_READY` | 本机 CAN FD 驱动处于可收发状态 |
| 9～15 | - | 保留，固定 `0` |

电源状态机取值：`0=OFF`、`1=MONITOR`、`2=RUN`、`3=LOW`、`4=BQ_WAKE`、`5=BQ_SHUTDOWN`、`6=FAULT`。

均衡位掩码使用连续逻辑编号：Bit 0～5 分别对应 Cell 1～6，Bit 6～15 固定为 `0`。线上字段不是 BQ76952 VC1、VC2、VC6、VC9、VC12、VC16 的稀疏物理位图。

### 5.2 `0x02` 六节电芯电压

应答长度为 20 字节。

| Byte | 类型/单位 | 内容 |
| ---: | --- | --- |
| 0～3 | - | 公共应答头 |
| 4～5 | `u16 / mV` | 逻辑 Cell 1 |
| 6～7 | `u16 / mV` | 逻辑 Cell 2 |
| 8～9 | `u16 / mV` | 逻辑 Cell 3 |
| 10～11 | `u16 / mV` | 逻辑 Cell 4 |
| 12～13 | `u16 / mV` | 逻辑 Cell 5 |
| 14～15 | `u16 / mV` | 逻辑 Cell 6 |
| 16～19 | `u32 / mV` | 总压；当前实现为 BQ Stack Voltage 镜像 |

这里的 Cell 1～6 是串联顺序。当前硬件在 BQ76952 内部对应 VC1、VC2、VC6、VC9、VC12、VC16，不能按连续 VC 引脚解释。

### 5.3 `0x03` SOH 与累计统计

应答长度为 32 字节。

| Byte | 类型/单位 | 内容 |
| ---: | --- | --- |
| 0～3 | - | 公共应答头 |
| 4 | `u8 / %` | 容量 SOH；无效时 `0xFF` |
| 5 | `u8 / %` | 健康趋势评分 |
| 6 | `u8 / %` | SOH 可信度 |
| 7 bit0 | `bool` | 容量 SOH 有效 |
| 7 bit1 | `bool` | 容量学习进行中 |
| 7 bit2～7 | - | 保留 |
| 8～11 | `u32 / mAh` | 已学习满充容量 |
| 12～15 | `u32 / mAh` | 累计充电吞吐量 |
| 16～19 | `u32 / mAh` | 累计放电吞吐量 |
| 20～23 | `u32` | 等效放电循环数 |
| 24～27 | `u32 / mAh` | 本轮容量学习净放电量 |
| 28～29 | `u16` | 有效容量学习次数 |
| 30～31 | - | 保留，固定 `0` |

未完成首次有效满电到空电学习时，查询结果为 `0x03`，SOH 为 `0xFF`；累计量和学习进度仍可读取。

| Byte | 类型 | 内容 |
| ---: | --- | --- |
| 0～3 | - | 公共应答头 |
| 4～5 | `u16` | Alarm Status |
| 6～7 | `u16` | Alarm Raw Status |
| 8～9 | `u16` | Battery Status |
| 10～11 | `u16` | Manufacturing Status |
| 12 | `u8` | FET Status |
| 13～15 | `u8[3]` | Safety Alert A/B/C |
| 16～18 | `u8[3]` | Safety Status A/B/C |
| 19～22 | `u8[4]` | PF Status A/B/C/D |
| 23 | `bool` | APP 故障摘要 |

## 6. TPDO1 `0x183`

TPDO1 长度固定为 32 字节，与整车协议对象 `0x2400` 一致。

| Byte | 类型/单位 | 内容 |
| ---: | --- | --- |
| 0～3 | `u32 / ms` | BMS 本次启动后的单调运行时间 |
| 4～5 | `u16` | 状态标志 |
| 6 | `u8` | 电源状态机状态 |
| 7 | `u8` | BQ76952 FET Status |
| 8 | `u8 / %` | SOC；无效时 `0xFF` |
| 9 | `u8 / %` | SOC 可信度 |
| 10 | `u8 / %` | SOH；无效时 `0xFF` |
| 11 | `u8 / %` | SOH 可信度 |
| 12～15 | `u32 / mV` | 总压；当前实现为 BQ Stack Voltage 镜像 |
| 16～19 | `i32 / mA` | 电流；正数充电，负数放电 |
| 20～21 | `u16 / mV` | 最低单体电压 |
| 22～23 | `u16 / mV` | 最高单体电压 |
| 24～25 | `u16 / mV` | 单体压差 |
| 26～27 | `i16 / 0.1 °C` | 电芯温度 |
| 28～29 | `u16` | 逻辑电芯均衡位掩码 |
| 30 | `u8 / %` | 健康趋势评分 |
| 31 | `u8` | 保留，固定 `0` |

低电量、严重低电量、恢复、故障发生和故障解除时，BMS 立即补发一帧相同布局的 TPDO1，不再发送旧私有事件 `0x100`。SOC 失效不会被误判为电量恢复；上位机以状态标志 Bit 6/7 和周期 TPDO1 收敛最终状态。

## 7. 上位机实现建议

- 查询事务序号由上位机递增，用 ID、命令和事务序号匹配应答；请求必须恰好为 3 字节。
- 建议查询超时从 300 ms 起步，超时后重试；本协议没有应用层 ACK。
- 收到 `DATA_INVALID` 时保留报文用于诊断，但不要把 `0xFF` 当作 255%。
- 使用状态标志判断字段有效性，不要只根据数值是否为零判断。
- 关键状态变化会立即补发 TPDO1，周期状态用于最终状态收敛；上位机不应只依赖单次变化帧。
- 未定义的命令必须视为只读协议扩展，不能默认解释成 MOS 控制。

例如查询状态摘要时，上位机发送标准 ID `0x600`、3 字节数据 `01 01 2A`；BMS 使用标准 ID `0x580` 返回 32 字节应答，其中前三字节仍为 `01 01 2A`，Byte 3 为执行结果。

## 8. 实现依据与待验证项

- FDCAN1 为标准 CAN FD、BRS，仲裁段 500 kbit/s、数据段 4 Mbit/s，位时序来自 `bms24v_platform/Core/Src/fdcan.c`；500 kbit/s / 1 Mbit/s 仍是已验证回退基线。
- 底层标准帧收发和合法 DLC 映射位于 `Int/Int_CanFd.c`。
- 查询、周期上报、事件队列和阈值状态机位于 `App/App_CanBms.c`。
- 电芯顺序、电流方向和采样有效性来自 `App/App_BatMan_Sample.c`。

当前 `pack_mv` 只是 Stack Voltage 的软件镜像，尚未独立采集 BQ PACK 引脚电压。CAN FD 实板互通、总线负载、无 ACK、bus-off 恢复、掉线恢复和长时间错误状态也尚未验证；这些项目在验证完成前均为 `Unknown`。
