# AI 充电曲线测试任务书

创建日期：2026-07-12  
计划执行日期：2026-07-13  
适用仓库：`lst92991-eng/bms`  
适用分支：`main`  
测试性质：必要代码清洗完成后的上板充电闭环测试。

## 1. 测试目标

本任务用于完成当前项目尚未闭环的充电验证。完整放电测试已经通过当前阶段验证，本任务不重复扩大放电测试范围，只做必要回归。

本次必须回答：

1. SC8815 能否从 standby 安全进入充电状态。
2. BQ CHG FET、SC8815 PSTOP/#CE 和充电请求是否按策略一致动作。
3. PACK、6 节单体和充电电流曲线是否连续、方向正确、无异常跳变。
4. 实际充电截止电压、最高单体、EOC 和停充原因是什么。
5. VBATS 外部分压 `200kΩ/10kΩ` 对应的实际截止是否接近项目目标 `25.2V`。
6. 充电温升、SC/BQ fault、保护状态和恢复行为是否符合预期。
7. 当前 OCC/COV/OTC 等相关阈值是否需要根据实测调整。
8. 清洗后的 PDSG、SC INT、RTOS 周期和外设启动策略是否没有破坏充电主链路。

## 2. 测试前置条件

全部满足后才能开始长时间充电：

- 必要清洗代码已经合入并记录 commit。
- Debug 或 Release 构建成功，烧录文件与 commit 对应。
- `PA5 / SC8815_INT` 已配置为 EXTI，ISR 只置 flag。
- 预放电状态机修改已通过基础测试。
- CAN、EEPROM 等必需外设初始化失败时不会进入正常 RUN。
- BQ 默认 CRC 为 disabled，Device Number 能稳定读回。
- SC8815 通信、STATUS、VBUS/VBAT/IBUS/IBAT 能稳定读取。
- R17/R18 实物确认为 `200kΩ/10kΩ`，无虚焊或短路。
- 电池包无鼓包、漏液、异常温升或明显单体失衡。
- 充电电源具有限流和过压保护，测试人员可立即断开输入。
- 测温、万用表和串口采集可用。

任一前置条件不满足，停止测试并记录原因。

## 4. 数据采集要求

### 4.1 默认 CSV

保留 Debug CLI 默认 CSV 输出：

```text
current_a,pack_v,cell1_v,cell2_v,cell3_v,cell4_v,cell5_v,cell6_v,frame_time_s
```

CSV 必须从充电器接入前开始采集，直到停充后至少继续记录 5 分钟，以观察回落和恢复。

### 4.2 周期诊断快照

每个关键阶段额外保存：

- `bq`
- `sc`
- `power`
- 必要时 `bqfast on`

不要让 BQ 连续监控和 CSV 同时交叉输出。切换输出模式时记录准确时间点。

### 4.3 外部测量

至少记录：

- 24V 输入电压和输入限流值。
- PACK 总压。
- 最高单体和最低单体。
- VBATS 引脚电压，尤其是接近满充时。
- 充电电流外部参考值。
- 电池、采样电阻、FET、SC8815 及主要功率器件温度。

## 5. 测试步骤

### 阶段 A：冷启动安全态

1. 不连接充电器，冷启动系统。
2. 确认 BQ Device Number 正常，SC8815 为 standby。
3. 确认无异常 CHG/DSG、PSTOP、#CE 动作。
4. 确认 CSV 连续输出，PACK 和 6 节单体合理。
5. 保存启动日志和一次 `bq/sc/power` 快照。

通过条件：系统进入预期安全状态，无 fault，无异常充电电流。

### 阶段 B：低限流接入

1. 输入电源设置为项目允许电压，先使用 `500mA` 输入限流。
2. 接入充电器，观察 SC INT、AC_OK、VBUS、VBAT 和功率状态。
3. 确认 SC 在配置完成前保持 PSTOP standby。
4. 确认 BQ CHG FET 与 SC 充电请求动作顺序一致。
5. 连续观察至少 10 分钟，记录电流、PACK、单体和温度。

立即停止条件：

- 任一单体异常上升或明显偏离其余单体。
- PACK/VBATS 与目标明显不一致。
- SC 报 VBUS short、OTP 或通信故障。
- BQ safety/PF 状态异常。
- 电流方向与软件约定相反。
- 任一器件出现异常温升、噪声、气味或波形。

### 阶段 C：保守运行电流曲线

低限流稳定后，按固件当前安全配置逐级验证，不允许跳级：

1. 确认当前 IBUS/IBAT 配置和软件限值。
2. 逐级提高输入能力，每一级至少稳定观察 10 分钟。
3. 当前阶段优先完成低限流和 `3A` 电池侧充电曲线。
4. 只有 `3A` 曲线、温升、单体一致性和停止逻辑全部合格后，才评估是否执行 `5A` 目标验证。
5. 每次调整前后保存 `sc` 和 `power` 快照。

不得为了得到漂亮曲线临时关闭 OVP、终止、短路折返、温度或 BQ 保护。

### 阶段 D：接近满充与截止

接近满充时重点记录：

- PACK 总压。
- VBATS 实测值。
- 最高/最低单体和压差。
- 充电电流下降过程。
- SC EOC 状态。
- BQ CHG FET 状态。
- `App_Power` 的满停或顶端均衡停充原因。
- SC8815 停止充电后的 PSTOP/#CE 状态。
- 最高器件温度。

不得无人值守完成首次接近满充测试。

### 阶段 E：停充后观察

1. 停充后继续采集至少 5 分钟。
2. 观察 PACK 和单体回落。
3. 记录是否出现不合理的反复启停。
4. 检查满停回差和顶端均衡恢复条件。
5. 保存最终 `bq/sc/power` 快照。

## 7. 合格判定

本轮充电闭环合格至少满足：

- 充电启动和停止动作可重复。
- CSV 无大段丢失、时间倒退或明显不合理跳变。
- PACK 与单体总和关系合理。
- 电流方向正确，外部参考与 BQ/SC 读数差异可解释。
- 最高单体没有超过项目允许范围。
- 实际截止电压、VBATS 和停止原因能够解释。
- SC/BQ 没有未解释 fault。
- 温升在硬件和电芯允许范围内，且测试记录完整。
- 满停后没有危险的高频反复启停。
- 清洗后的 SC INT、RTOS 周期和初始化策略没有造成回归。

不满足时输出失败结论，禁止把未完成测试写成“已通过”。

## 8. AI 分析任务

AI 收到原始 CSV、串口日志和测试条件后，应完成：

1. 清洗时间轴并标记充电接入、升流、恒流、接近满充、停充和回落阶段。
2. 绘制 PACK、电流、6 节单体、最高/最低单体和压差曲线。
3. 计算每阶段平均电流、斜率、异常跳变和数据缺口。
4. 对比 BQ、SC 和外部测量值。
5. 标记所有 fault、EOC、CHG/DSG、PSTOP/#CE 和状态切换时刻。
6. 核对阈值表，区分“代码问题”“参数需标定”“硬件事实待确认”和“测试数据不足”。
7. 输出是否允许最终闭环的明确结论。
8. 生成可直接并入最终开发文档的测试章节草稿，但不得虚构缺失数据。

## 10. 最终输出

测试结束后，`result.md` 必须给出以下四选一结论：

- `PASS`：允许进入最终文档冻结。
- `PASS_WITH_ACTIONS`：主链路合格，但有明确的非阻塞标定或文档动作。
- `FAIL_SOFTWARE`：需要修改代码后重测。
- `FAIL_HARDWARE_OR_SETUP`：硬件或测试条件不满足，禁止软件侧猜测性修复。
